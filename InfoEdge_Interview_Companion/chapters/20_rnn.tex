\section{Why sequences need memory}
The meaning of ``bank'' depends on earlier words; tomorrow's application count depends on the last few weeks; the next job a seeker clicks
depends on what they clicked before. A feed-forward network takes a fixed-size input and has no memory. We want a model that reads a
sequence one step at a time, keeps a running summary (a \textbf{hidden state}), and handles any length.

\section{The vanilla RNN}
At each time step $t$, with input $\mathbf x_t$ and previous hidden state $\mathbf h_{t-1}$:
\[ \mathbf h_t = \tanh(W_{hh}\mathbf h_{t-1} + W_{xh}\mathbf x_t + \mathbf b),\qquad \hat{\mathbf y}_t = W_{hy}\mathbf h_t + \mathbf c. \]
The \emph{same} weights are used at every step (weight sharing across time). Unrolled over time, an RNN is a very deep network with tied weights.
\begin{example}[: RNN by hand]
Scalar RNN $h_t = \tanh(0.5h_{t-1} + x_t)$, $h_0 = 0$, $x_1 = 1$, $x_2 = -1$. $h_1 = \tanh(1) = 0.762$. $h_2 = \tanh(0.381 - 1) = \tanh(-0.619) = -0.551$.
\end{example}
Parameters (input size $d$, hidden size $h$): $W_{xh}$: $hd$, $W_{hh}$: $h^2$, bias $h$: total $h(d + h + 1)$. For $d = 10$, $h = 20$: $20\cdot31 = 620$.

\subsection{Shapes of sequence problems}
\begin{itemize}
\item Many-to-one: sentiment of a review; ``will this seeker apply'' from their session.
\item One-to-many: image captioning.
\item Many-to-many (aligned): POS/NER tagging of resume tokens.
\item Many-to-many (seq2seq): translation, summarising a JD.
\end{itemize}

\section{Backpropagation through time (BPTT)}
Unroll the RNN over the sequence, compute the loss (summed over steps), and backpropagate through the unrolled graph; gradients for the shared weights
are summed over time steps. For long sequences, \textbf{truncated BPTT} backpropagates only through the last $k$ steps (e.g. 50), carrying the hidden state
forward but cutting the gradient: cheaper, but cannot learn dependencies longer than $k$ through gradients.

\section{The vanishing/exploding problem in RNNs}
The gradient of the loss at step $t$ with respect to $\mathbf h_{t-k}$ contains the product $\prod_{j}\frac{\partial\mathbf h_j}{\partial\mathbf h_{j-1}} = \prod_j
\text{diag}(\tanh'(\cdot))W_{hh}$: the same matrix $W_{hh}$ multiplied $k$ times. If its largest singular value (times $\tanh'\le1$) is below 1, the product
shrinks exponentially: the network cannot learn that a word 30 steps back matters. If above 1, it explodes.
\begin{example}[: how fast it vanishes]
Factor 0.5 per step: after 10 steps $0.5^{10} = 0.001$. It first drops below $10^{-3}$ at step 10 ($0.5^{10} = 9.8\times10^{-4}$). Factor 1.5: after 20 steps about
3{,}325.
\end{example}
Exploding is handled by gradient clipping. Vanishing needs an architectural fix: gates.

\section{LSTM: a memory with gates}
The LSTM adds a separate \textbf{cell state} $\mathbf c_t$, a conveyor belt of memory, and three \textbf{gates} (sigmoid outputs in $(0,1)$ that act as soft switches).
\begin{align*}
\mathbf f_t &= \sigma(W_f[\mathbf h_{t-1},\mathbf x_t] + \mathbf b_f) &&\text{forget gate: how much old memory to keep}\\
\mathbf i_t &= \sigma(W_i[\mathbf h_{t-1},\mathbf x_t] + \mathbf b_i) &&\text{input gate: how much new information to write}\\
\tilde{\mathbf c}_t &= \tanh(W_c[\mathbf h_{t-1},\mathbf x_t] + \mathbf b_c) &&\text{candidate content}\\
\mathbf c_t &= \mathbf f_t\odot\mathbf c_{t-1} + \mathbf i_t\odot\tilde{\mathbf c}_t &&\text{update memory (additive!)}\\
\mathbf o_t &= \sigma(W_o[\mathbf h_{t-1},\mathbf x_t] + \mathbf b_o) &&\text{output gate: how much memory to reveal}\\
\mathbf h_t &= \mathbf o_t\odot\tanh(\mathbf c_t) &&\text{hidden state / output}
\end{align*}
$[\mathbf h_{t-1},\mathbf x_t]$ means the two vectors concatenated; $\odot$ is element-wise multiplication.

\begin{example}[: one LSTM step]
$c_{t-1} = 2$, $f = 0.5$, $i = 0.8$, $\tilde c = 0.5$, $o = 0.5$. $c_t = 0.5\cdot2 + 0.8\cdot0.5 = 1.4$. $h_t = 0.5\tanh(1.4) = 0.5\cdot0.885 = 0.443$.
\end{example}

\subsection{Why the LSTM does not vanish}
The cell update is \emph{additive}: $\mathbf c_t = \mathbf f_t\odot\mathbf c_{t-1} + \dots$, so $\partial\mathbf c_t/\partial\mathbf c_{t-1} = \mathbf f_t$ (plus indirect terms),
with no squashing non-linearity and no repeated weight matrix on this path. If the forget gate stays near 1, gradients flow back over many steps almost unchanged
(the ``constant error carousel''). The network \emph{learns} when to keep and when to forget.
\begin{example}[: cell path vs vanilla]
Forget gate 0.9 for 10 steps: $0.9^{10} = 0.35$. Vanilla RNN with factor 0.5: $0.001$. Same 10 steps, 350 times more gradient.
\end{example}
\textbf{Forget gate bias initialised to 1}: so $f\approx\sigma(1) = 0.73$ at the start: the cell remembers by default until it learns otherwise.

\subsection{Parameter count}
Four blocks (f, i, $\tilde c$, o), each with weights for $[\mathbf h,\mathbf x]$ and a bias: $4h(d + h + 1)$. For $d = 10$, $h = 20$: $4\cdot20\cdot31 = 2{,}480$.
Keras \code{LSTM(128)} on 64 features: $4\cdot128\cdot(64 + 128 + 1) = 98{,}816$. (PyTorch uses two bias vectors, adding $4h$.)

\section{GRU: a lighter LSTM}
Two gates, no separate cell state:
\begin{align*}
\mathbf z_t &= \sigma(W_z[\mathbf h_{t-1},\mathbf x_t]) &&\text{update gate}\\
\mathbf r_t &= \sigma(W_r[\mathbf h_{t-1},\mathbf x_t]) &&\text{reset gate}\\
\tilde{\mathbf h}_t &= \tanh(W[\mathbf r_t\odot\mathbf h_{t-1},\mathbf x_t])\\
\mathbf h_t &= (1 - \mathbf z_t)\odot\mathbf h_{t-1} + \mathbf z_t\odot\tilde{\mathbf h}_t.
\end{align*}
The update gate interpolates between keeping the old state and writing the new one (merging LSTM's forget and input gates); if $\mathbf z_t = 0$ the state is copied
unchanged. Parameters $3h(d + h + 1)$: $3\cdot20\cdot31 = 1{,}860$. GRUs train faster with similar accuracy on many tasks; LSTMs can be slightly better on very
long or complex dependencies.

\section{Variants and training tricks}
\begin{itemize}
\item \textbf{Stacked} (deep) RNNs: the hidden sequence of layer 1 is the input of layer 2.
\item \textbf{Bidirectional}: one RNN reads left-to-right, another right-to-left; concatenate (hidden 128 per direction gives 256). Good for tagging and
  classification; \emph{not} usable for forecasting or real-time generation, which cannot see the future.
\item \textbf{Seq2seq} encoder--decoder: the encoder compresses the input into a context vector; the decoder generates the output. A single fixed vector is a
  bottleneck for long inputs; \textbf{attention} (Bahdanau) lets the decoder look at all encoder states at every step (20 input $\times$ 15 output tokens gives 300 attention
  weights), which led to Transformers.
\item \textbf{Teacher forcing}: during training, feed the true previous token to the decoder rather than its own prediction (fast, stable; mismatch at inference
  = exposure bias).
\item \textbf{Padding and masking}, \textbf{packed sequences} for variable lengths; \textbf{gradient clipping}; \textbf{dropout} between layers (and variational dropout
  across time).
\item \textbf{CTC loss} (connectionist temporal classification) for speech recognition and handwriting, where input frames and output characters are not aligned.
\end{itemize}

\section{Time series with deep learning}
\textbf{Framing}: turn a series into supervised windows: use the last $L$ values (lookback) to predict the next value (or next $H$). 1{,}000 daily values, lookback 30,
next 1: $1000 - 30 = 970$ samples.
\textbf{Before an LSTM, beat the baselines}: naive (tomorrow = today), seasonal naive (same day last week), moving averages, ARIMA/ETS, gradient boosting on lag features.
They are often hard to beat on short, noisy series.
\textbf{Good practice}: scale using training statistics only; split by time (walk-forward validation); add calendar features (day of week, holidays, month-end
hiring cycles) and exogenous variables (job postings drive applications); predict differences or ratios for trending series.
\textbf{Model options}: LSTM/GRU; 1-D CNN/TCN (dilated causal convolutions); Transformers for long horizons (Informer, PatchTST); DeepAR (probabilistic, many related
series); N-BEATS; and GBMs on lags remain very strong.

\section{Why Transformers replaced RNNs}
RNNs process tokens sequentially (no parallelism over time), struggle with very long dependencies (information must survive many steps), and compress
everything into a fixed-size state. Self-attention connects every pair of positions in one step and parallelises across the sequence (Chapter 21). RNNs remain
useful for streaming and on-device settings with small memory.

\begin{practical}[: sequence models at InfoEdge]
\begin{itemize}
\item \textbf{Session-based recommendation}: predict the next job a seeker views from their click sequence (GRU4Rec historically; now Transformers like SASRec).
\item \textbf{Forecasting}: daily applies per category, recruiter demand by city (Talent Pulse ``expected hike''), call-centre volume for telecalling staffing.
\item \textbf{Speech}: the GenAI slide's voice agents (calling premium seekers, AI REX bot calling) use ASR and TTS; older ASR used LSTMs with CTC, today Transformer
  models.
\end{itemize}
\end{practical}

\section{Interview questions}

\begin{qa}{\pyq{INT: DL models for time series} Which deep learning models would you use for time series, and what are their trade-offs?}
\oneline{RNN-family models (vanilla RNN, LSTM, GRU) process the series step by step with a memory; LSTM/GRU fix the vanilla RNN's vanishing gradients with gates; 1-D CNNs/TCNs and
Transformers are parallel alternatives; and I would always compare against simple baselines and gradient boosting on lag features.}
\why
\textbf{Vanilla RNN}: simple, but cannot learn long-range dependencies (vanishing gradients through repeated $W_{hh}$ and tanh).
\textbf{LSTM}: cell state with additive updates and forget/input/output gates; remembers over hundreds of steps; more parameters ($4\times$ RNN).
\textbf{GRU}: update and reset gates, no cell state; $3\times$ RNN parameters; trains faster; similar accuracy.
\textbf{TCN / 1-D CNN}: dilated causal convolutions; parallel; fixed receptive field.
\textbf{Transformers}: attention across the whole window; best for long horizons with lots of data; quadratic cost in window length.
\textbf{Practical recipe}: windows with lookback $L$; scale with training stats; walk-forward validation; calendar and exogenous features; compare MAE/MAPE with seasonal-naive and
LightGBM on lags; ensemble.
\worked Daily applications to Data Science jobs: seasonal naive (same weekday last week) MAPE 14\%; LightGBM with lags 1--28 and calendar features 8\%; LSTM 9\%; ensemble 7.5\%.
\pushes \emph{``Why might an LSTM lose to LightGBM here?''} Short, noisy series and few examples; GBMs exploit engineered lags and calendar effects very efficiently.
\end{qa}

\begin{qa}{\pyq{INT: LSTM internal structure} Draw the LSTM cell, write its equations, and explain each gate.}
\oneline{The LSTM keeps a cell state updated additively as $\mathbf c_t = \mathbf f_t\odot\mathbf c_{t-1} + \mathbf i_t\odot\tilde{\mathbf c}_t$, where the forget gate decides what to keep,
the input gate what to write, and the output gate what part of $\tanh(\mathbf c_t)$ becomes the hidden state.}
\why Each gate is a sigmoid layer over $[\mathbf h_{t-1},\mathbf x_t]$, producing numbers in $(0,1)$ per memory slot. The candidate $\tilde{\mathbf c}_t$ is a tanh layer proposing
new content. Intuition with a resume: on reading ``Previously at TCS'' the forget gate may clear ``current employer'' information; on ``Currently at Infosys'' the input gate
writes it; the output gate exposes it when the model needs to predict ``company''.
\worked $c_t = 1.4$, $h_t = 0.443$ in the example above.
\end{qa}

\begin{qa}{\pyq{INT: how the LSTM avoids vanishing gradients} Why do LSTMs mitigate vanishing gradients?}
\oneline{Because the cell state is updated additively with a learned forget gate, so the gradient along the cell path is multiplied by $\mathbf f_t$ (which can stay near 1) rather than by
a repeated weight matrix and a squashing derivative.}
\why $\partial\mathbf c_t/\partial\mathbf c_{t-1}\approx\text{diag}(\mathbf f_t)$. Over 10 steps with $f = 0.9$: 0.35, versus 0.001 for a vanilla RNN with factor 0.5. LSTMs do not
eliminate the problem (forget gates below 1 still decay), but the network controls the decay. Exploding gradients can still occur via other paths: clip.
\end{qa}

\begin{qa}{\pyq{INT: BPTT} What is backpropagation through time, and what is truncated BPTT?}
\oneline{BPTT is ordinary backpropagation applied to the RNN unrolled across time steps, summing gradients of the shared weights over steps; truncated BPTT limits the backward pass
to the last $k$ steps to save memory and time.}
\why Memory grows with sequence length because activations at each step must be stored. Truncation trades long-range learning for cost.
\end{qa}

\begin{qa}{\pyq{OA: LSTM applications} Where are LSTMs typically used?}
\oneline{Speech recognition (historically with CTC), language modelling and machine translation before Transformers, handwriting recognition, time-series forecasting, and sequence
tagging.}
\end{qa}

\begin{qa}{\pyq{INT: GRU vs LSTM} Compare GRU and LSTM.}
\oneline{A GRU merges the forget and input gates into one update gate, adds a reset gate and drops the separate cell state, so it has about 25\% fewer parameters and trains faster, with
similar accuracy on many tasks; LSTMs can be better for very long, complex dependencies.}
\why GRU: $h_t = (1 - z)h_{t-1} + z\tilde h_t$, a convex combination. If $z = 0$, the state is copied: the GRU's version of the constant error carousel.
\end{qa}

\begin{qa}{\pyq{INT: sliding windows for time series} 1{,}000 daily values, lookback 30, predict the next day: how many training samples, and how do you split them?}
\oneline{970 samples; split by time (e.g. last 20\% as validation) or walk-forward, never randomly, and fit scalers on the training period only.}
\end{qa}

\begin{qa}{Compute $h_2$ for $h_t = \tanh(0.5h_{t-1} + x_t)$ with $h_0 = 0$, $x_1 = 1$, $x_2 = -1$.}
\oneline{$h_1 = 0.762$, $h_2 = \tanh(-0.619) = -0.551$.}
\end{qa}

\begin{qa}{How many parameters do an RNN, LSTM and GRU with input 10 and hidden 20 have (one bias per gate)?}
\oneline{620, 2{,}480 and 1{,}860.}
\end{qa}

\begin{qa}{Why is tanh, not ReLU, the default activation inside RNNs and LSTMs?}
\oneline{tanh is bounded, keeping the recurrent state from growing without limit when the same weights are applied repeatedly; ReLU's unbounded output can make the state and
gradients explode in recurrences (though ReLU RNNs with identity initialisation exist).}
\end{qa}

\begin{qa}{Why initialise the LSTM forget-gate bias to 1?}
\oneline{So that initially $f\approx0.73$ and the cell remembers by default, letting gradients flow over long ranges early in training instead of the cell forgetting everything
at $f\approx0.5$.}
\end{qa}

\begin{qa}{\deep Can you use a bidirectional LSTM for stock-price or application-count forecasting?}
\oneline{Not for the forecast itself: the backward direction reads future values that are not available at prediction time, which is leakage; bidirectional models suit tasks where the
whole sequence is known (tagging, classification).}
\end{qa}

\begin{qa}{What is teacher forcing, and what problem does it create?}
\oneline{Training the decoder with the true previous token as input instead of its own prediction; it speeds and stabilises training but creates exposure bias: at inference the model
sees its own mistakes, which it never practised recovering from (mitigated by scheduled sampling).}
\end{qa}

\begin{qa}{Why did attention help seq2seq models?}
\oneline{A single fixed-length context vector cannot hold all of a long input; attention lets the decoder build a different weighted summary of all encoder states at each output step,
focusing on the relevant input words.}
\end{qa}

\begin{qa}{\deep Why do Transformers outperform RNNs on long text, and when would you still use an RNN?}
\oneline{Self-attention connects any two positions in one step (path length 1 vs $n$ for RNNs) and processes all positions in parallel on GPUs; I would still use an RNN for streaming or
on-device settings with strict memory limits, or short sequences where its simplicity suffices.}
\end{qa}

\begin{qa}{What is CTC loss used for?}
\oneline{For sequence problems where input frames and output labels are not aligned (speech, handwriting); it sums over all alignments using a blank symbol, so no frame-level labels are
needed.}
\end{qa}

\begin{qa}{\deep A seeker's click sequence today: J1, J5, J9. How would you predict the next job they will view?}
\oneline{Treat it as next-item prediction: embed job IDs (plus content features for new jobs), run a GRU or a self-attention model over the session, and score candidate jobs by dot product
with the final state, trained with sampled softmax on historic sessions, evaluated by recall@20 and MRR on later sessions.}
\why Add time gaps, filters (location), and blend with the seeker's long-term profile. This is what ``Reco'' in the Seeker AI engines needs.
\end{qa}

\begin{qa}{How do you handle sequences of different lengths in a batch?}
\oneline{Pad them to a common length and use a mask so padded steps do not affect outputs or the loss, or use packed sequences (PyTorch) so the RNN skips padding; bucketing similar
lengths reduces wasted computation.}
\end{qa}
